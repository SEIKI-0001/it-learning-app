# ITパスポート学習コーチ 収益化キャンペーン設計

## 目的

2026年8月10日までに、自己購入を除く外部顧客から、Stripe手数料控除後で100米ドル相当以上を得る。

達成判定にはStripeの本番取引と残高を使う。円換算は達成判定日の日本銀行公表レートを使い、売上総額ではなく決済手数料控除後の金額で判定する。

## 現状と前提

- アプリは `https://it-learning-app.vercel.app` で本番公開されている。
- Stripe本番アカウントはカード決済・銀行入金ともに有効である。
- 本番Stripeには月額980円、買い切り1か月980円、3か月2,340円、6か月3,480円の価格が存在する。
- 6か月プランのCheckout、Webhook、Pro権限付与、購入履歴は既存実装で動作する。
- 直接連絡できる既存見込み客は0人である。
- 新しい高額商品は作らず、既存の6か月プランを販売する。
- 既存の `.gitignore` と `.projects/` の変更は本施策の対象外とする。

## 採用する商品

### 基本商品

- 商品名: ITパスポート学習コーチ Pro 6か月
- 価格: 3,480円（税込・買い切り）
- 自動更新: なし
- 提供内容:
  - 学習記録の継続保存
  - 合格準備度、復習、学習計画などのPro機能
  - Claude SonnetによるAI採点を1日10回まで
  - 購入完了時点から6か月のPro権限

### 期間限定特典

- キャンペーン期間: 公開日から2026年8月10日23時59分（日本時間）まで
- 対象: キャンペーンページ経由で6か月プランを購入した先着6名
- 特典:
  - 20分のオンライン学習計画相談を1回
  - 相談後のLINEフォローを1回
- 合格保証は行わない。提供価値は、試験日と生活時間に合わせた具体的な学習計画を作ることに限定する。

### 売上目標

6件の購入で総額20,880円となる。国内カード手数料3.6%を単純控除した概算は20,128円であり、為替変動や一部返金に備えた余裕を持つ。

最低必要件数は5件を目安とするが、キャンペーン運用上の目標は6件とする。

## ユーザー導線

1. 見込み客が公開キャンペーンページを読む。
2. 未ログインの場合はGoogleまたはLINEで登録する。
3. 登録後、キャンペーンページへ戻る。
4. 「3,480円で6か月始める」を押す。
5. 既存の `one_6m` プランでStripe Checkoutを開始する。
6. 決済完了後、既存Webhookが購入を記録し、Pro権限を6か月延長する。
7. キャンペーンページへ戻り、権限反映中または反映済みの状態を表示する。
8. 購入者は公式LINEを開き、購入時のメールアドレスを送る。
9. 運営者がStripe上の購入情報と照合し、相談日時を決める。
10. 20分相談を実施し、相談後にLINEで学習計画の要点を1回送る。

Checkoutをキャンセルした場合は課金・権限変更を行わず、キャンペーンページへ戻して再試行できるようにする。

## システム設計

### 公開キャンペーンページ

公開パス `/campaign/august-2026` を追加する。ページには次を表示する。

- 誰向けの商品か
- 6か月Proの機能
- 3,480円の買い切りであること
- 自動更新がないこと
- 期間限定特典と先着人数
- 合格保証ではないこと
- 返金条件
- 特定商取引法表示、プライバシーポリシーへのリンク
- ログイン状態に応じた購入ボタン

既存LPにもキャンペーンページへの導線を追加する。既存の通常料金表は維持し、キャンペーンを別商品に見せない。

### 認証と戻り先

キャンペーンページは未ログインでも閲覧できる公開ページにする。購入ボタンを押した未ログインユーザーは `/login?next=/campaign/august-2026` に移動し、Google OAuth後に同じページへ戻る。

Checkout APIの戻り先ホワイトリストに `/campaign/august-2026` を追加し、オープンリダイレクト防止を維持する。

### Checkout

価格と商品は既存の `one_6m` と `STRIPE_PRICE_ID_PRO_6M` を再利用する。新しいStripe商品、価格、クーポンは作らない。

Checkout APIはキャンペーンキー `august_2026` を任意で受け取り、Stripe Checkout Sessionのmetadataへ保存する。任意文字列は受け付けず、この固定値だけを許可する。これにより通常の6か月購入とキャンペーン経由購入をStripe上で区別する。

Stripe Checkoutの購入確定ボタン付近には `custom_text.submit.message` を使い、買い切り、自動更新なし、提供期間、返金条件、特定商取引法表示の確認先を短く表示する。購入者が自社ページとStripeの最終確認画面の両方で主要条件を確認できるようにする。

### Webhookと権限付与

既存の以下の仕組みを変更せず再利用する。

- Stripe署名検証
- Price ID照合
- `checkout.session.completed` の処理
- `billing_purchases` の冪等記録
- `pro_until` の6か月延長
- Webhook失敗の記録と管理画面からの再処理

キャンペーンmetadataは販売経路の識別だけに使い、Pro権限の判定条件には使わない。

### 購入完了状態

キャンペーンページは `checkout=success` を検出したら、決済完了とWebhook反映に時間差があり得ることを表示する。課金APIを再取得し、Pro反映済みなら購入完了状態へ切り替える。

反映が遅い場合でも成功を断定せず、「決済を確認中」と表示する。運営者は既存の管理画面でWebhook失敗を確認し、必要なら再処理する。

## 法務・プライバシー表示

### 特定商取引法表示

公開パス `/legal/tokusho` を追加し、少なくとも次を表示する。

- 役務の対価: 3,480円（税込）
- 商品以外の負担: インターネット接続料金は購入者負担
- 支払方法と時期: Stripeによるカード決済、購入時に即時決済
- 提供時期: 決済完了後、Webhook反映を経て通常数分以内
- 提供期間: Pro権限6か月
- 自動更新がないこと
- キャンペーン特典の提供方法
- 返金条件
- 動作環境: モダンブラウザとインターネット接続
- 事業者情報の開示請求方法

事業者の氏名、住所、電話番号は、消費者庁の通信販売広告Q&Aに示された省略方法を用いる。ページ上で、消費者から請求があれば広告表示事項を記載した書面または電子メールを遅滞なく提供することを明示し、公式LINEを請求窓口にする。運営者は購入判断に間に合うよう請求へ対応できる状態を維持する。

参照:

- https://www.no-trouble.caa.go.jp/qa/advertising.html
- https://www.no-trouble.caa.go.jp/what/mailorder/

### 返金条件

購入日を含む7日以内で、かつ20分相談の実施前に公式LINEから申し出た場合は、理由を問わず全額返金する。相談実施後は、サービスの重大な不具合または二重決済を除き返金しない。

返金条件はキャンペーンページ、特定商取引法表示、Stripe Checkoutの購入前に確認できる箇所へ明瞭に表示する。

### プライバシー

公開パス `/privacy` にプライバシーポリシーを追加し、次を含める。

- Google、LINE、Stripe、Supabaseを通じて取得する情報
- 学習履歴、AI採点履歴、購入情報の利用目的
- 相談特典の本人確認に購入時メールアドレスを使うこと
- 第三者サービスへの送信
- 保存、安全管理、問い合わせ方法

LINEで受け取った購入時メールアドレスは、購入照合と相談提供のためだけに使う。

## 集客と販売運用

既存見込み客が0人のため、広告費を使う前に手動の高意図集客を行う。

### 毎日の活動

- ITパスポート受験者が使う公開SNSで、学習上の質問や悩みに対して1日10件を上限に個別性のある回答をする。
- 回答内で即座に購入リンクを押し付けず、相手が追加情報を求めた場合にキャンペーンページを案内する。
- 1日2件まで、アプリの無料教材、操作教材、令和8年度公開問題など実物が分かる投稿を行う。
- 同一文面の大量投稿、無関係なハッシュタグ、無差別DMは行わない。
- 投稿ごとに日付、媒体、内容、反応、ページ誘導、購入の有無を記録する。
- 集客記録は `docs/operations/2026-august-revenue-campaign-log.md` に日付順で残す。

### 先着特典の管理

- Stripeの本番Checkout Sessionをキャンペーンmetadataと支払完了時刻で並べ、先着順を決める。
- 運営者は購入通知ごとに件数を確認し、6件到達後はキャンペーンページを「特典受付終了」に切り替える。
- 6件目と同時刻帯に決済が重なり、購入時点でページに特典受付中と表示されていた場合は、超過分も特典対象として扱う。
- 特典終了後も通常の6か月プランは3,480円で購入できるが、相談特典は付かないことを明示する。

### 日次判断

- ページ閲覧がない場合は投稿の入口と配信場所を変える。
- 閲覧はあるが登録がない場合は対象者と価値提案を明確にする。
- 登録はあるがCheckout開始がない場合は料金、返金条件、提供内容の説明を改善する。
- Checkout開始後の失敗がある場合は技術障害を最優先で直す。
- 8月5日時点で購入が2件未満なら、価格は下げず、20分相談の無料体験枠を設けて信頼形成を強化する。

## エラー処理

- 未ログイン購入: ログインへ誘導し、戻り先を保持する。
- Stripe未設定: 購入ボタンを準備中にし、Checkout APIは503を返す。
- Checkout作成失敗: 再試行可能なメッセージを表示する。
- Checkoutキャンセル: 課金されていないことを表示する。
- Webhook遅延: 権限反映を断定せず、状態を再取得する。
- Webhook失敗: 既存管理画面で検出し、冪等な再処理を行う。
- LINE未設定: 特典受付ができないため、キャンペーンの購入CTAを有効化しない。
- キャンペーン終了後: 特典受付を終了し、通常の6か月プラン導線へ戻す。

## テスト

### 自動テスト

- 公開キャンペーンページが未ログインで表示できる。
- ログイン後の戻り先がキャンペーンページになる。
- Checkout APIが `one_6m` と許可済みキャンペーンキーをStripeへ渡す。
- 不正なキャンペーンキーをmetadataへ渡さない。
- キャンペーンページ以外への不正な戻り先を拒否する。
- 成功、キャンセル、Checkout失敗、Webhook反映待ちを正しく表示する。
- キャンペーン終了後は特典付きCTAを表示しない。
- 特定商取引法表示とプライバシーポリシーが公開ルートとして表示できる。
- 既存の月額・買い切りCheckout、Webhook、購入履歴テストが引き続き通る。

### 検証コマンド

- `npm test`
- `npm run typecheck`
- `npm run lint`
- `npm run build`

### 本番スモークテスト

- キャンペーンページと法務ページが200を返す。
- 未ログインからGoogleログイン後にキャンペーンページへ戻る。
- 本番Checkoutが3,480円、買い切り、6か月商品として開く。
- キャンセル後に課金・権限変更がない。
- Stripeの本番Webhookエンドポイントが有効である。

自己購入は売上達成に含めない。本番スモークテストではCheckout表示まで確認し、自己決済は行わない。

## 完了条件

実装完了は次のすべてを満たした状態とする。

1. キャンペーン、特定商取引法表示、プライバシーポリシーが本番公開されている。
2. 未ログインからCheckoutまでの導線が本番で動作する。
3. 既存決済とWebhookのテストが通る。
4. 集客記録を開始できる運用フォーマットがある。
5. Stripe本番取引で外部顧客の購入を識別できる。

目標達成は、上記に加えて、2026年8月10日までにStripe手数料控除後の外部顧客売上が100米ドル相当以上になったことをStripe本番残高・取引と日本銀行公表レートで確認した時点とする。

## 対象外

- 新しいStripe商品・価格の作成
- 月額プランや既存買い切りプランの価格変更
- 合格保証
- 有料広告の出稿
- 自動予約システム
- CRMの新規導入
- 大規模な管理画面改修
- 無差別DMや自動投稿
