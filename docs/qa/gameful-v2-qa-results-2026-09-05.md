## 0. 結論

## 1. 重大度「高」

### H-1. `/growth-check` が永久に「読み込み中…」— GF-P0-003 の画面が表示できない

```
[ジャーニー] J5
[端末/幅]   Chromium / 390px（幅非依存）
[事前状態]  オンボーディング直後／1レッスン完了後のいずれでも再現
[手順]      /growth-check へ直接アクセス、またはリロード
[観測]      LoadingScreen「読み込み中…」から永久に進まない
[期待]      成長の根拠一覧、または任意ミニ確認が表示される
[観点]      A / E
[重大度]    高（機能全体が到達不能）
[原因]      app/growth-check/page.tsx の `useState(() => {...})` 初期化関数が
            state 未読込（undefined）の初回レンダーで実行され、view が null に固定される。
            useAppState は必ず undefined から始まり effect で値を入れるため、
            初期化関数が再実行されることはない。
            結果 `if (state === undefined || state === null || view === null)` が
            恒真になり LoadingScreen を返し続ける。
```

`/today` のカードからのクライアント遷移でも同じ（コンポーネントは新規マウントされ、
初回レンダーの state は undefined のため）。

**既存テストが素通りした理由**: `test/GrowthCheckPage.test.tsx` は `useAppState` を
モックして state を最初から与えるため、初回レンダーが undefined になる実挙動を再現しない。
回帰テストは「state が undefined の初回レンダーを経てから表示される」形にする必要がある。

### H-2. 未ログインで突破試験を完遂できない（J7→J8 が通らない）

```
[ジャーニー] J7 / J8
[事前状態]  CP1 の解放条件を満たし、出題に足るトピックを完了済み・未ログイン
[手順]      /checkpoint/cp1/final →「突破試験に挑む」→ 全6問に解答
[観測]      ① 開始時:「評価セッションを開始できませんでした。もう一度お試しください。」
            ② ①を迂回して解答完了後:「採点結果を保存できませんでした。もう一度お試しください。」
               → 合否が表示されず、CPも進まない
[期待]      未ログインでもローカル完結で合否が出る（§6 非機能「未ログイン」）
[観点]      A / E
[重大度]    高（CP進行が不能）
[失敗API]   401 POST /api/assessment-sessions
            401 POST /api/question-attempts/save
```

**回帰の所在**: PR #33 のマージ時点（`e7cbf84`）の同ページは
`saveQuestionAttemptsForCurrentSession` を使っており、この関数は 401 を
`authState:"anonymous"` として**graceful に扱い例外を投げない**。`uid` が null なら
DB保存を飛ばすだけで、採点と CP 進行はローカルで成立していた。
現行 main は exam-readiness 統合で、サーバー永続化の成功を採点結果表示の前提に
変更した（`Assessment finalization was not fully persisted` を throw → catch で
persistenceError 表示）。同じ前提は `/mock-exam`・過去問・テーマ別試験・
分野まとめテストの各 Runner にも入っている（同一文言が6箇所）。

**未検証**: ログイン済みユーザーで成功するかは、ローカルに Supabase の
環境変数が無いため確認できていない。本番相当環境での再確認が必要。
なお `401 GET /api/session/state` と `401 GET /api/exam-readiness/current` は
画面を壊さず、これらは問題ない。

### M-2. 復帰導線の分量が要件の3〜5分に対して約15分

```
[ジャーニー] J12
[事前状態]  progress.lastPlayedAt を5日前に設定
[観測]      「5日ぶりです。まずは前に学んだところを、約15分だけ思い出すところから戻りましょう。」
            （2件 × 約8分 + 約7分）
```

## 3. 重大度「低」

### L-1. 「今日の3ミッション」の中身が折りたたみの中だけにある

`/today` の可視領域には宝箱の「今日の3ミッション達成で開けられる」しか出ず、
3件の内容・進捗・差し替え（`GF-P1-009`）は `<details>`「今日の状況」を開かないと見えない。
達成条件を示されたユーザーが、その条件を同じ画面で確認できない（観点A）。

### L-2. バッジ獲得トーストが突破試験の問題文に重なる

出題中の画面中央にトーストが縦に積まれ、設問と選択肢を覆った（観点C）。
QAでは seed により5件同時獲得させたため増幅されている。通常プレイでの同時獲得は
1〜2件と見込まれるが、表示位置が本文の上である点は変わらない。

### L-3. 学習量「5分」でルートが約8分

最小の学習単位が8分のため、5分を選んでも約8分の1件になる。
「意味のある完了単位が存在する」（受け入れ基準）は満たすが、
「選択時間内に収まる」（要件本文）は満たさない。ヘッダの「1件・約8分」は正直な表示。

## 5. 実施できていない項目

| J10 ヒートマップの粒度 | 履歴が1日分しかなく、複数日の粒度は未検証 |
| J11 図鑑の収集状況 | 単語帳未消化（103語すべて未学習）の状態しか見ていない |
