# ゲームフルデザインv2 実機QA計画

正仕様は `docs/requirements/gameful-design-v2.md`。本書はその P0/P1 実装を
**実機で通して確かめ、Tracker を `IMPLEMENTED` → `VERIFIED` へ昇格させるための手順書**である。

対象要件: `GF-P0-001`〜`005`、`GF-P1-001`〜`011`
対象外: `GF-P0-006`（LINE通知・未着手）、`GF-P2-*`（DEFERRED）

---

## 1. QAの目的

「動くか」だけを見ない。v2 が守ろうとした約束が実機で成立しているかを見る。
各ジャーニーで、機能確認とは別に **§2 の共通観点** を必ず採点する。

## 2. 共通観点（全ジャーニーで採点する）

| # | 観点 | 落ちている状態の例 |
|---|---|---|
| A | 次に何をすべきか迷わない | 画面を開いて3秒以内に「次の一手」が指させない |
| B | Primary CTA が明確 | 同じ強調度のボタンが2つ以上並ぶ／Primaryが折りたたみの中 |
| C | ゲーム要素が学習導線を邪魔しない | 宝箱・演出が Primary より先に目に入る |
| D | 同じ情報・目標が重複していない | 同じバッジ進捗や同じCP条件が1画面に2回出る |
| E | 成長実感が適切なタイミングで伝わる | 学習直後に何が進んだか分からない／踊り場で成長確認が出ない |
| F | 報酬が学習成果より強く見えない | XP・かけらの表示が理解度・準備度より目立つ |
| G | モチットの発話が実データと整合 | 事実と違う励まし（未達成なのに「達成したね」等） |
| H | モバイルで情報過多でない | 1画面目にカードが5枚以上／横スクロールが発生 |
| I | 用語が画面間でぶれない（`GF-P1-011`） | 同じ概念が別名で出る（§7 の対照表で照合） |

判定は各ジャーニーで `OK` / `NG` / `要検討` の3値。`NG` は §8 のテンプレで記録する。

## 3. 環境と端末

| 項目 | 指定 |
|---|---|
| 端末 | iPhone 実機（Safari）を主、Android Chrome を副、デスクトップ Chrome 1280px を確認用 |
| 幅 | 375px / 390px / 430px を最低1回ずつ通す |
| 環境 | 本番相当（Vercel preview または production） |
| アカウント | ①新規（未ログイン）②Googleログイン済み ③LINE連携済み の3系統 |
| 設定 | `prefers-reduced-motion: reduce` でも1周する（演出の停止確認） |

## 4. 状態の作り方

実機で全状態を自然に作るのは現実的でないため、**演出とロジックの検証を分ける**。

- **ロジック起点で作る状態**（学習完了・バッジ獲得・ストリーク・デイリー達成）は
  実際に操作して作る。ここを seed で作ると `GF-P0-005` の成果差分の正しさが検証できない。
- **到達に時間がかかる前提状態**（CP条件の充足直前、離脱n日、CP突破直後）は
  DevTools から `localStorage["fequest:appstate"]` を編集して作ってよい。
  編集後は必ずリロードし、`progress.checkpointProgress` 配下だけを触る。
- **離脱日数**は `localStorage` の最終学習日を過去日にして作る。端末の時計は変えない
  （時計変更は他の日付ロジックを巻き込むため）。
- seed で作った状態から進めた結果は、DB同期（ログイン時）後にリロードして
  **消えていないこと**まで見る。

## 5. ジャーニー

各ジャーニーは「事前状態 → 手順 → 期待 → 共通観点の採点」で構成する。

### J1. 新規ユーザー → onboarding → /today

- 事前: localStorage クリア、未ログイン
- 手順: `/` → 学習をはじめる → プラン作成 → `/today` 到達
- 期待:
  - 確認画面を挟まず `/today` へ直行する
  - 1画面目に「今日の最優先」1件と、その所要時間・行動効果が出る
  - 未設定の試験日が「未設定」と正直に出る（架空の数字を出さない）
  - 下部ナビは5件
- 重点: A / B / H

### J2. 今日のPrimary学習を開始（`GF-P0-001` `GF-P0-002`）

- 事前: J1 直後
- 手順: 「今日の最優先」カードの CTA から学習に入る
- 期待:
  - 開始前に「これが進みます」が最大3件、確定する更新だけ出る
  - 同じトピックが「今日のルート」で `いま挑戦中` として一致している
  - Primary と同格の強調が他に無い
- 重点: B / C / D

### J3. 学習完了 → 成長差分（`GF-P0-005`）

- 事前: J2 の学習を最後まで完了
- 手順: 確認問題まで解き切り、完了画面を見る
- 期待:
  - 何が変わったか（理解度・復習キュー・バッジ条件）が事実として出る
  - 事前に予告した「これが進みます」と結果が矛盾しない
  - XP は表示されるが、理解度より前面に出ない
- 重点: E / F

### J4. バッジ獲得（`GF-P0-002` / 報酬まわり）

- 事前: 必須バッジ条件をあと1件で満たす状態
- 手順: 条件を満たす学習を完了 → 演出 → `/badges` を開く
- 期待:
  - 獲得演出が学習結果の後に出る（結果を隠さない）
  - 追加ドロップが出た場合、必須バッジ・準備度・CP進行に触れる文言が一切ない
  - `/badges` の「必須＝突破試験の解放に必要」と `/plan` の条件表示が一致
- 重点: C / D / F / I

### J5. CP中間 → 成長確認（踊り場）（`GF-P0-003`）

- 事前: CP の途中（突破試験が未解放）で、比較材料がある状態
- 手順: `/today` の「ここまでの成長をふりかえる」→ `/growth-check`
- 期待:
  - 既存記録だけで比較できるときは追加出題しない
  - 材料不足時のみ任意ミニ出題が出て、スキップが同格に置かれる
  - 復習キュー・期限切れ・severity>=80 の弱点が出題に混ざらない
  - 突破試験が解放済みのときは踊り場を出さない
- 重点: C / E

### J6. 復習対象があるときの復習優先

- 事前: 期限到来の復習が1件以上ある状態
- 手順: `/today` を開く
- 期待:
  - Primary が新規学習ではなく復習になる
  - `/review` の分類（間違い/苦手/予定）に正しく入る
  - 突破試験が解放済みでも、期限復習が先に来る
- 重点: A / B

### J7. CP条件達成 → 突破試験（`GF-P1-011` の主戦場）

- 事前: 必須バッジ・3分野着手・正答率の全条件を満たした状態
- 手順: `/today` の解放通知 → `/plan` のゲートカード → `/checkpoint/{cp}/final`
- 期待:
  - 3画面すべてが **突破試験** と呼ぶ（最終問題・ボス戦が出ない）
  - 試験の結果は「合格」で、CPの結果は「突破」。混ざっていない
  - 解放条件・問題数・合格ラインが3画面で同じ数値
  - 条件未達のとき「あと0個」のような矛盾表示が出ない
  - 不合格でもペナルティ文言がなく、間違えたテーマが復習に入る
- 重点: A / D / I

### J8. CP突破 → モチット成長・達成演出（`GF-P1-003`）

- 事前: J7 で合格
- 手順: 合格画面 → `/plan` の地図 → モチット
- 期待:
  - CP→次CP の段階変化が1度だけ出る（リロードで再演出しない）
  - モチットの成長段階が実際の進行と一致
  - 記念称号が `/rewards` の「突破の記念」に出て、かけらを消費していない
- 重点: E / F / G

### J9. 今日の3ミッション → 宝箱 → 報酬（`GF-P1-005` `GF-P1-006` `GF-P1-009`）

- 事前: 当日の3ミッションが未達成
- 手順: 3件を達成 → 宝箱を開ける → 3択が出たら選ぶ → `/rewards`
- 期待:
  - 呼称が `今日の3ミッション` に統一され、`n/3 達成` と整合
  - 差し替えは未着手の1件のみ・1日1回、着手済みの進捗を失わない
  - 3択はすべて当たりで、選ばなかった損失が無いと明示される
  - ドロップ名と `/rewards` の所持名・交換コストの表記が一致（かけら）
  - 受け取りは冪等（リロードで二重付与されない）
- 重点: C / D / F / I

### J10. `/progress` → ヒートマップ・あゆみ（`GF-P1-004`）

- 事前: 数日分の学習履歴
- 手順: `/progress` を開く
- 期待:
  - ヒートマップの粒度が実データと一致（空白日を埋めない）
  - 「次の解放」がランク／突破試験／モチット成長の実在する解放だけ
  - 準備度・順調/遅れの指標が `/plan` と一致（二重定義しない）
- 重点: D / E

### J11. 単語帳 → 図鑑（`GF-P1-008`）

- 事前: 単語帳を一定数消化
- 手順: `/glossary` → 図鑑表示
- 期待: 収集状況が実進捗と一致し、未収集を煽らない
- 重点: E / F

### J12. 離脱状態 → 復帰導線（`GF-P1-002`）

- 事前: 最終学習日を3日前・7日前にして2回試す
- 手順: `/today` を開く
- 期待:
  - 山積みの未完了ではなく、3〜5分の短い再開点が先に出る
  - 空いた日数は事実として一度だけ触れ、責める文言が無い
  - やらずに通常導線へ進める
  - 見出しが「おかえりなさい」で、`ミッション` という語をUIに出さない
- 重点: A / C / I

### J13. 学習量の選択（`GF-P1-001`）

- 事前: 復習と新規学習が両方ある日
- 手順: `/today` で 5分 / 15分 / 30分 / おまかせ を切り替える
- 期待:
  - どの分量でも期限復習・優先弱点が後回しにならない
  - 5分でも意味のある完了単位が1つ以上ある
  - 30分を強制・優遇しない
- 重点: A / B

### J14. 合格宣言・モチット命名（`GF-P1-007` `GF-P1-010`）

- 手順: `/plan` から宣言、モチットに命名
- 期待: 未宣言・未命名でも不利益が無い。取り消せる。学習評価に影響しない
- 重点: F

## 6. 非機能・回帰

| 項目 | 確認 |
|---|---|
| モバイル幅 | 375/390/430px で横スクロールが起きない。改行崩れが無い |
| reduced-motion | 紙吹雪・発光・sheen が停止し、情報は残る |
| a11y | Primary CTA がボタン/リンクとして読み上げられる。色だけでレア度を伝えない |
| 未ログイン | 全ジャーニーがローカルだけで完結し、保存失敗で体験が止まらない |
| 端末間マージ | 端末Aで宝箱受取・かけら獲得 → 端末Bでログイン → 双方の獲得が消えない |
| 冪等 | 報酬受取・演出イベントの再送でXP・かけら・履歴が二重にならない |
| 初期表示 | `/today` の初回表示でレイアウトが大きく飛ばない |

## 7. 用語対照表（`GF-P1-011` の照合用）

QA中に下記の「廃止した表記」を1つでも見つけたら NG として記録する。

| 概念 | 正 | 廃止 |
|---|---|---|
| CP進行のゲート試験 | 突破試験 | 最終問題 / ボス戦 / 突破試験（最終問題） |
| /plan の現在CP見出し | いま挑戦中のチェックポイント | クエスト進行中 |
| CPを進める条件 | 次のチェックポイントに進む条件 | — |
| デイリー3件 | 今日の3ミッション（進捗は `n/3 達成`） | 3ミッション / ミッション n/3 |
| 離脱後の再開導線 | おかえりなさい | 復帰ミッション（UI表示として） |
| 補助報酬 | かけら（ノーマル/レア/宝箱のかけら） | 欠片 / ノーマル欠片 / レア欠片 |
| 分野横断テスト（`/checkpoint/[id]`） | 分野まとめテスト | 突破試験 |
| 突破試験の結果 | 合格（合格する/合格済み/n問正解で合格） | 突破済み / クリア済み |
| チェックポイントの結果 | 突破（CPを突破/突破済み/突破の記念） | — |

内部識別子（`finalExam*`・`frag-common`・`badgeFragments` 等）は変更していないため、
DevTools やDBに旧語が見えても NG ではない。**画面に出る文言だけ**を対象とする。

## 8. 不具合記録テンプレ

```
[ジャーニー] J7
[端末/幅]   iPhone 15 Safari / 390px
[事前状態]  CP1 必須バッジ3/3・3分野着手済み
[手順]      /plan → ゲートカード
[観測]      「あと0個の必須バッジを集めると…」と表示
[期待]      残条件（3分野）を指す文言
[観点]      A / I
[重大度]    中（誤解を生むが進行は可能）
```

重大度は 高（進行不能・データ喪失・虚偽表示）／中（誤解・迷い）／低（表記ゆれ・見た目）。
