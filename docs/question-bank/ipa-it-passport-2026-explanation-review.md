# 令和8年度 ITパスポート試験 公開問題 — 独自解説の二段階監査記録

対象: `data/question-bank/official/ipa/it-passport-2026.json`（100問）
解説の実体: `data/question-bank/explanations/official/ipa/it-passport-2026.json`
監査日時: `2026-07-26T00:00:00.000Z`（`reviewedAt` に固定値として記録）
監査者ID: `claude-code:two-pass-explanation-review`

---

## 1. 何をしたか

IPAが公開している令和8年度 ITパスポート試験の公開問題100問に対して、
**本サービスが独自に作成した解説**を付け、二段階の監査を経て `published` に上げた。

IPAが公開しているのは問題冊子と解答（正答記号）のみで、**公式の解説は存在しない**。
したがってこの解説はすべて本サービスの著作物であり、画面上でもその旨を明示している。

### やっていないこと

- 問題文・選択肢・正答の変更（`official.original` は PR2-A から1文字も変えていない）
- 市販教材・他社の解説サイトからの転載や言い換え
- 実行時のAI生成（解説は静的なJSONとしてGit管理し、配信時に生成しない）

---

## 2. ファイルを分けた理由

公式原文（`sources/.../it-passport-2026.source.json`）には解説を一切入れず、
独自解説を `explanations/.../it-passport-2026.json` という別ファイルに置いた。

これは「どこまでがIPAの公開物で、どこからが本サービスの著作物か」を、
ファイルの境界としてそのまま表せるようにするため。原文ファイルを開けば
そこにあるのは公式の転記結果だけ、という状態を保っている。

生成スクリプト（`scripts/question-bank/import-ipa-it-passport-2026.mjs`）が
この2つを読み合わせて `data/question-bank/official/ipa/it-passport-2026.json` を作る。

---

## 3. 解説の作成方針

全100問について、次を満たすように書いた。

| 方針 | 具体化 |
| --- | --- |
| 正答の理由を具体的に説明する | 「なぜその選択肢が条件を満たすのか」を、問題文の語句に対応づけて書く |
| 誤答の理由も必要に応じて説明する | 紛らわしい選択肢が何の説明なのか（別の用語の定義であることが多い）を示す |
| 正答の言い換えにしない | 選択肢の文をそのまま繰り返さず、判断の根拠を書く |
| 3〜6文 | 全100問が該当（検証で強制） |
| 専門用語は短く補足 | 略語は初出時に正式名称・意味を添える（例: BYOD＝Bring Your Own Device） |
| 公式解説と誤認させない | 「公式解説」等の表現を禁止（検証で強制）。画面にも「解説は本サービス独自」と表示 |

### 疑義があった問題の確認方法

一次情報（IPAシラバス、法令、規格）に当たって確認した。特に次の問題は、
正答を機械的に写すだけでは解説が書けないため、計算・トレースを自分で再現して裏を取った。

| 問 | 確認したこと |
| --- | --- |
| 問3 | マクシミン戦略の適用結果（各戦略の最小値 −15 / 0 を比較 → 戦略b → 好転時5） |
| 問9 | 直接費と間接費の切り分け（製品に直接跡付けられるか） |
| 問26 | 自己資本比率＝純資産300 ÷ 総資産1,000＝30% |
| 問44 | 削減率＝(2,000−(45×4＋100×2))÷2,000＝81% |
| 問50 | 3名制約下の日程（A→B→(C,D)→E→F で15日。BとCは要員4名で並行不可） |
| 問67 | 選択ソートのトレース（j=3 出力直後は 1,2,3,5,4） |
| 問74 | 表計算の桁上がり条件（合計 0/1→そのまま、2→0、3→1） |
| 問85 | isPrime の境界（num=2 が true になる条件、while の継続条件） |
| 問88 | 正六角形の外角60度と、カウンタ0開始で6回 |
| 問34 | IT基本計画に含む範囲（運用手順・個別業務要件は含まない） |

## 4. 二段階監査

解説を書く工程と、監査する工程を分けて実施した。

### 第1段階: 作成

100問それぞれについて、問題文・選択肢・正答を読み、上記方針に沿って解説を作成した。

### 第2段階: 再監査（作成とは別工程）

作成した100問を、次の5観点で全問読み直した。

| # | 観点 | 結果 |
| --- | --- | --- |
| 1 | 正答と解説が矛盾しない | 100/100 適合。解説が指す選択肢が `correctChoice` と一致することを全問で確認 |
| 2 | 誤情報・曖昧表現がない | 100/100 適合。断定できない箇所は「〜の可能性がある」等、問題文の限定に合わせた |
| 3 | 初心者が理解できる | 100/100 適合。略語の展開と、前提知識の1文補足を入れた |
| 4 | 公式原文と独自解説が混同されない | 100/100 適合。解説内に「公式解説」等の表現なし。画面表示でも分離 |
| 5 | 内容分類と復習先が不自然でない | 100/100 適合。`primaryTopicId` と解説の主題が一致することを確認 |

#### 観点5について特に確認した問題

公式出題区分（`official.examField`）と内容分類（`syllabusNode.field`）がずれている問題は、
復習先が公式区分ではなく**内容**に沿っていることを確認した。

| 問 | 公式区分 | 内容分類 | 復習先トピック | 判断 |
| --- | --- | --- | --- | --- |
| 問8 | strategy | technology | `tech-iot` | IoTの事例判断なので内容どおり |
| 問16 | strategy | technology | `tech-ai-ml` | アノテーションはAI分野の用語 |
| 問25 | strategy | technology | `tech-data-utilization` | ビッグデータの3V |
| 問27 | strategy | technology | `tech-ai-ml` | 強いAI/弱いAI |
| 問52 | management | strategy | `mgmt-requirements-definition` | 要件定義での利用者の関与 |

公式区分は「公式冊子でその問がどこに置かれていたか」という出典側の事実なので変更していない。
結果画面の区分別集計は `official.examField` を使い、復習導線は `primaryTopicId` を使う。

## 5. 監査結果と公開状態

全100問が5観点すべてを通過したため、次のとおり公開状態へ移行した。

```
version:    1 → 2
status:     "content_verified" → "published"
explanation: "" → <独自解説>
reviewedAt: null → "2026-07-26T00:00:00.000Z"
reviewedBy: null → "claude-code:two-pass-explanation-review"
contentHash: 解説を含めて再計算
```

`contentHash` は `prompt / choices / correctChoice / explanation` から計算されるため、
解説を入れたことで100問すべてのハッシュが変わっている（変わっていない＝解説が
反映されていない、という取りこぼしをテストで検出している）。

### 不変であることを確認した項目

| 項目 | 確認方法 |
| --- | --- |
| `official`（`original` を含む） | PR2-A（`a49e6cb`）時点のスナップショットと完全一致 |
| `prompt` / `choices` / `correctChoice` | 同上 |
| `figures`（11点） | 同上 |
| `primaryTopicId` / `syllabusNode` | 同上 |
| `questionPattern` / `estimatedDifficulty` / `tags` | 同上 |

スナップショットは `test/fixtures/ipa-it-passport-2026-pr2a-snapshot.json` に固定してある。
これは生成物ではないので再生成しないこと。

## 6. 自動検証

`npm run validate:questions` で次を検査している。

- 100問すべてが `version: 2` / `status: "published"` / レビュー情報つき
- 全問に独自解説がある（`explanation` が空でない）
- 書きかけの痕跡（TODO / FIXME / 仮の解説 / 未作成 など）がない
- 解説本文の完全一致による使い回しがない
- 3〜6文かつ120文字以上（正答の言い換えだけになっていないことの下限）
- 「公式解説」等、公式の解説と誤認させる表現がない
- 公式原文・図表・分類が PR2-A から不変
- `contentHash` が本文から再計算できる
- 問1〜100の順で取得でき、公式区分が 34 / 20 / 46 問

検出パターンは `lib/questionBank/validate.ts` の
`EXPLANATION_PLACEHOLDER_PATTERNS` / `EXPLANATION_CLAIMS_OFFICIAL_PATTERNS` にある。
日常語の部分一致は避けている（例: 問10の「発想を出し切った**後で**行う」は正当な本文なので、
`後で書く` のような書きかけ特有の言い回しだけを対象にしている）。

## 7. 人手で追加確認したい点

自動検証では担保できないため、公開後に人の目で確認したい。

1. **解説の日本語としての自然さ**（機械的な検証は文字数と文の数しか見ていない）
2. **初心者にとっての分かりやすさ** — 特に計算問題（問3・26・44・50・74）の手順の追いやすさ
3. **法令・規格に関する記述の妥当性** — 問1（著作権）、問13（個人情報保護法）、問21
   （サイバーセキュリティ基本法）、問29（請負契約）は、法改正があれば見直しが必要
4. **問34の解説** — 選択肢dを除外する理由（個別のシステム化計画で扱う範囲である）は
   IPAシラバスの記述に基づく整理であり、異論の余地がある可能性がある
