# PRD: X Growth PDCA Engine v1

## 事業目標
ITパスポート初心者に役立つ独自の教育投稿の閲覧を増やし、学習サービスへの質の高い流入・無料体験・登録につなげる。無目的な投稿数、リポスト操作、偽装エンゲージメントは評価しない。

## 実装すべきループ
1. PLAN: 前回の実験結果と教材在庫を踏まえ、次週の検証仮説と投稿パターンを提案し保存。
2. DO: 安全性・ソース整合性が確認された本文候補を生成し、予め割付した実験variantを選び投稿（既存runnerを再利用）。
3. CHECK: 投稿済みIDから24時間前後/72時間前後のXメトリクスを読んでスナップショット保存。UTM訪問・登録の既存DB集計と結合。
4. ACT: 両variantの72時間インプレッションと補助指標を比較。小標本では勝者を断定せず仮説と次の実験を提案。許可された範囲だけ自動設定に反映。

## KPI
- PRIMARY (Phase 1): `impressions_at_72h` = 72時間付近（実際の採取時刻を必ず保存）の投稿インプレッション。distinct viewersではない。
- SECONDARY: 72hのいいね、リポスト、返信、引用、ブックマーク、反応率（イベント数/表示回数）。フォロワー増加（任意）。
- FUNNEL: 投稿のUTM別サイト訪問・訪問者・登録。リンクなし投稿はプロフィール経由で訪れる可能性があるため投稿別流入0を全流入0と混同しない。
- QUALITY: 投稿成功率、品質検査合格率、重複・事実誤認0件、X/AIの月額推定・実支出。

## 初回実験（初期設計案、実施は計測安定後）
- 変数: 冒頭の伝え方（定義型 vs 質問型）だけを変える。
- 固定: 投稿時刻07:00 JST、1日1回、リンクなし、教材の選定基準、本文の説明構成、ハッシュタグ数、文字数の大まかなレンジ。
- 期間: 28日・各variant 14件を目標。曜日による偏りを少なくするバランス割付。投稿失敗・メトリクス未取得は有効サンプルに数えない。
- 低サンプルなので結果は「探索的」。20%差でも有意と断定しない。翌月に別のテーマ・説明形式で再現を検証。

## 投稿のパターン候補（段階導入）
- 質問から始まるミニクイズ（答えと理由も投稿中に含める）
- 日常に置き換えるたとえ話（例の限界・例外を認識させる）
- 初学者が誤解しやすいポイントの訂正
- 誤った選択肢がなぜ違うかの説明
- 短い記憶術（根拠あるものだけ）
- 図解画像付き投稿（画像アップロード・アクセシビリティ・権利検証後の別フェーズ）
- サービス紹介・サイト誘導（上流の閲覧試験と分けて検証）

## 生成方法
`Source`に事実・出典・権利区分・関連lesson/topic/URLを保持。LLMは許可された「フック」「語り順」「見せ方」「例え」を生成し、事実・公式の問題文や正解はロックする。AI出力の検証は構造チェック+根拠事実照合+文字数/類似性+別系統品質レビュー+必要な人間レビュー。自己申告品質フラグだけで通過させない。

## 役割分担
- Claude Code/Ralph Loop: 開発・テスト・修正を反復し、仕様を実装する（開発時のみ）。
- GitHub Actions: 投稿・測定・週次分析のスケジュール実行（本番運用時）。
- Supabase: 投稿・実験条件・メトリクス・週次レビューの永続化。
- AI: 表現候補/説明/分析/新仮説を生成。外部操作・テーブル変更・予算変更を直接決定しない。
- 決定論的コード: 割付、上限、統計、学習・選択、投稿禁止/承認、コスト制御。

## 不採用
- 本番でClaude Codeを無限にループさせる。
- 早期に多数の変数（時刻、画像、リンク、題材）を同時に変える。
- AIの「良い投稿」という主観だけを教師信号にする。
- 無許可の自動返信・いいね・フォロー・連投・トレンド便乗。
- 投稿失敗時に品質基準を下げる。推測値でXメトリクスを埋める。
- 現時点でプロフィール訪問者の識別/取得を当然可能と仮定する。

## 稼働制限
本番の新しい自動投稿やリンク付き投稿には運用者の明示承認を要する。既存投稿ワークフローの `X_POST_ENABLED`、`X_POST_DRY_RUN`、上限、重複・不明投稿ガードは保持する。
