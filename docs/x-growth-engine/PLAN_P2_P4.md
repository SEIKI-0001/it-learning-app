## 設計方針（決めたこと）
1. **事実は承認済みデータから一字一句コピーする。** 投稿表現は「型（content style）」のテンプレートで決まり、LLM は事実も variant も選ばない。
   検証は LLM と独立に行う。承認済みデータから候補をもう一度作り直し、本文が完全一致することを確認する。加えて、文字数・重複・禁止表現・メタデータの一致を見る。
2. 型のレジストリ（`lib/growth/xGrowth/styles.ts`）。初期の型:
   - `definition_first`: 現在の投稿と同じ形。対照群。
   - `question_first`: 問いかけから始める。
   - `misconception`: `confusedWith` / `trapExplanations` / `differenceAxis` を使う。いずれも承認済みデータ。
   - `mini_quiz`: 選択肢は `confusedWith`。正解と一行説明も投稿に含める。
   - `analogy`: 承認済みの「たとえ」ライブラリがあるときだけ使える。初期の項目は draft なので、本番では使えない。
   - `kind: "text" | "image"` を持たせ、画像の型を後から足しても実験モデルを変えずに済むようにする。
3. **割付は決定論的。** 実験開始日からの日数 d と週 w = floor(d/7) について、variant = ((d mod 7) + w + seedBit) mod 2（当初の (d + w) では週の切れ目で反転せず偏ったため修正）。2週間で、各曜日に A と B が1回ずつ入る。対象外のテーマの日は実験に入れない。
4. **実験は2つの variant だけ。** 実験に使うトピックは、両方の型が使えるものの共通部分から、variant と関係なく決める。これで偏りを防ぐ。
5. **失敗時の扱い。** 実験用の候補が作れなければ、既存の投稿経路に戻す。その投稿は実験の標本に数えず、理由を記録する。タグ付けが失敗したら、投稿を止めて失敗として記録する。
6. **既存の動作を保つ。** `X_GROWTH_EXPERIMENTS_ENABLED=true` が無ければ、今の経路とまったく同じ動きをする。本番の投稿頻度・時刻・上限は変えない。
7. **P3 の判定は決定論的なルールで行う。** 勝者は自動で決めない。最低標本数・欠損率・曜日やトピックの偏り・外れ値で結論が変わらないことをすべて満たしたときだけ「探索的な有望」とする。別の実験で同じ方向に再現したら「検証済み」とする。それでも本番への反映は人の承認が必要。AI は解釈の文章を書くだけで、文章中の数値は計算結果と照合する。
8. **P4 は全工程をオフラインで通しテストする。** PGlite に本物の migration を適用し、偽の X・偽の AI を使う。workflow はすべて既定で停止。本番での有効化は人の承認が必要。
